# Spec: v0.2 companion addon, SavedVariables ingest, Characters / Ledger / Adventures

Status: **PM approved, pending Julia** · Author: @coder2 · 2026-10-05 (rev 2: PM review notes)

v0.1 knows the game folder, the WTF tree, backups and when WoW runs. v0.2 adds what only the game knows: who each character is, what they carry, how much gold they have, and what happened in each session. A small companion addon (**ForeverBuddy**) writes that to its SavedVariables at logout, the app ingests it, keeps the history in its own database, and shows it on the Characters, Ledger and Adventure screens of the round-3 mocks.

Builds on `docs/specs/core-fs.md` (safe IO, write gate, backups, `sv` parser) and `docs/specs/feature-matrix.md` (the data source and verdict for every field; row numbers below are that table's). Everything the addon reads is still unconfirmed on the live client until the probe runs (§8, gate G1).

**Ground rules (unchanged).** The app never touches the network for this; the addon has no network either. The app only writes into the game folder through the write gate, with WoW closed. Nothing destructive ever depends on a parse result.

## 2. The ForeverBuddy addon

### Files and TOC

`ForeverBuddy/ForeverBuddy.toc` + `ForeverBuddy.lua` (one file, no libraries, no XML).

```
## Interface: 16001
## Title: ForeverBuddy
## Notes: Notes down each character at logout for WoW Forever Buddy. No network; writes only its own SavedVariables.
## Version: 0.2.0
## SavedVariablesPerCharacter: ForeverBuddyDB
```

**Decision: per-character SavedVariables.** Each character writes `WTF/Account/<A>/<Realm>/<Char>/SavedVariables/ForeverBuddy.lua`. Playing two characters in one game session can't overwrite one with the other (matrix flag 8), "Exit Now" skipping the account-level file doesn't matter, and the app knows the character from the path even if the identity block were damaged.

### Hard rules

1. **Retail API only** (matrix fact 1): `C_Item`, `C_Container`, `C_Bank`, `C_TooltipInfo`, `C_AddOns`. No Classic globals.
2. **Every `RegisterEvent` is `pcall`-wrapped** (fact 6). An unknown event is skipped and recorded in `_meta.missing_events`.
3. **Every API call goes through one guard**, as in the probe: `local v = read(fn, ...)` = `pcall`, then `nil` if the API is missing, errors, or returns a secret value (`issecretvalue` / `issecrettable`). A guarded `nil` is never written as a zero. The count of secret results per session goes into `_meta.secret_hits`.
4. **No reliance on read-back.** On `PLAYER_LOGIN` the addon builds this session's data from live APIs. What the client loaded from disk is only used to carry forward old *sessions* and the last bank/mail state (below), and only if it validates (`_meta.schema` matches). If the client didn't load it, the file still ends up correct for this session; at worst older sessions the app never saw are lost.
5. **Does nothing visible of its own:** no frames, no chat output, no server requests beyond `RequestTimePlayed` and `RequestRaidInfo` once per login. No item use, mail, money or AH actions.
6. **Never taints.** The addon never replaces or hooks-by-replacement any Blizzard or secure function. **So the "Total time played" chat lines stay:** `TIME_PLAYED_MSG` isn't a `CHAT_MSG_*` event, so `ChatFrame_AddMessageEventFilter` can't drop it, and the only way to hide it is replacing `ChatFrame_DisplayTimePlayed`, which taints chat. The two lines appear once per login, the same as typing `/played`.
7. **Bounded:** at most 2,000 events per session, at most 10 sessions kept in the file, and money points coalesced to one per 60 s. Over a cap, the oldest are dropped and `_meta.truncated = true`.

### What it captures

`character` (once per login, refreshed at logout):
`name, surname, realm, guid, class (file token), race, sex, faction, level, guild {name, rank}`. Rows 6, 11. `surname` is `UnitName`'s second return, which on Forever is the character's surname (probe run 1: `"Ellygie", "Vargur"`, with the WTF folder `Ellygie-Vargur`). It's absent when there is none. `realm` is `GetRealmName` ("Classic Beta PvP 2").

`snapshot` (rebuilt at logout, plus at `/reload`):

| Field | API (matrix row) |
|---|---|
| `at` | `GetServerTime()` |
| `money` | `GetMoney` (9) |
| `xp, xp_max, rested, rest_state` | `UnitXP/UnitXPMax`, `GetXPExhaustion`, `GetRestState` (7) |
| `ilvl {avg, equipped}` | `GetAverageItemLevel` (8) |
| `played {total, level}` | `TIME_PLAYED_MSG` after `RequestTimePlayed` once per login, plus seconds since (10). After `/reload` it's taken from the file just written, not asked again (the request prints to chat). |
| `zone {zone, subzone, map}` | `GetRealZoneText`, `GetSubZoneText`, `C_Map.GetBestMapForUnit` (11) |
| `equipped[slot] = link` | slots 1–19, `GetInventoryItemLink` (12) |
| `bags[bag] = {name, size, free, items[slot] = {link, count}}` | bags 0–5, `C_Container.*` (13). An empty bag slot has no entry. |
| `bank = {at, bags[bagID] = {size, free, items[slot] = {link, count}}}` | the main bank (`Enum.BagIndex.Bank`, -1 on run 1) plus each `C_Bank.FetchPurchasedBankTabIDs` tab, read at `BANKFRAME_OPENED` and on `BAG_UPDATE_DELAYED` / `PLAYERBANKSLOTS_CHANGED` while open (14). **Carried forward** from the loaded file when this session had no bank visit; absent if it never had one. |
| `mail = {at, items[] = {sender, subject, money, cod, days_left, items[] = {link, count}}}` | at `MAIL_INBOX_UPDATE` while the mailbox is open, first 50 letters, 16 attachments each (15). Carried forward like `bank`. |
| `professions[] = {name, skill, max, line, spec}` | `GetProfessions` (up to five indices, any nil), `GetProfessionInfo` (16). `line` is the skill line id; `spec` only when ≥ 0. |
| `lockouts[] = {name, difficulty, reset_at, raid}` | `RequestRaidInfo` at login → `UPDATE_INSTANCE_INFO`, `GetSavedInstanceInfo`, locked ones only (17). Carried forward if none came this session. |
| `rest_state` | the name `GetRestState` returns ("Rested"). |

`character` adds `class` (file token), `race` (file token), `sex`, `faction`, `level` and `guild {name, rank}` to V1's identity.

`items[itemID] = {name, quality, ilvl, icon, class, subclass, sell}`: static info for every item seen this session (row 19), so the app can show names and qualities offline. Info that isn't cached yet is requested with `C_Item.RequestLoadItemDataByID` (once per item per session) and filled in on `ITEM_DATA_LOAD_RESULT`. "Seen" means equipped, in the bags, bank or mail, or gained. Fields come from `C_Item.GetItemInfo`'s returns 1, 3, 4, 10, 11, 12 and 13 (name, quality, item level, icon file id, sell price, class id, subclass id), per probe run 1.

`sessions[]` (this one appended to those carried forward, newest last):
`{id = login server time, login, logout, start = {money, xp, level, zone}, events[]}`.

| Event kind | Source (matrix row) | Fields |
|---|---|---|
| `zone` | `ZONE_CHANGED_NEW_AREA` (32), only when the zone changes | `t, zone, instance` (`true` inside an instance, else absent) |
| `level` | `PLAYER_LEVEL_UP` (33) | `t, level` |
| `money` | `PLAYER_MONEY` (31), coalesced: a change within 60 s of the last point updates that point's `money` | `t, money` |
| `quest` | `QUEST_TURNED_IN` (36) | `t, id, title, xp, money` |
| `death` | `PLAYER_DEAD` (34) | `t, zone` (no killer: restricted) |
| `repair` | while a merchant is open, a drop in `GetRepairAllCost` on `UPDATE_INVENTORY_DURABILITY` (34). Not read at `MERCHANT_CLOSED`, when the cost may already read 0. | `t, cost` |
| `gain` / `lose` | `BAG_UPDATE_DELAYED` diff of item counts across bags 0–5 plus inventory slots 1–23 (35, 37), so equipping isn't losing | `t, item` (item id), `count, how`. Lose `how`: `sold` at a merchant, `mailed` at a mailbox, else `used`. Gain `how`: `bought`, `mail`, else absent (looted or made). |
| `encounter` | `ENCOUNTER_END`, success only (pcall-registered) | `t, id, name` |

Instance entry ("Entered Stratholme") is a `zone` event with `instance = true`. Each session also has `start = {money, xp, level, zone}` from login, and the zone events only record changes from there.

Bag diff rules: the first scan (at `PLAYER_ENTERING_WORLD`, or the first bag update if that event is missing) is only a baseline. While the bank is open, changes aren't logged and closing it takes a new baseline: moving items isn't gaining or losing them. If any bag slot reads secret, that scan is skipped (otherwise the items would seem to vanish) and the next readable one logs the difference. An event argument that arrives secret leaves its field out, and an encounter whose success is secret isn't logged.

### The SavedVariables contract

One top-level table per file, so any cut inside it is a parse error (`sv` module contract):

```lua
ForeverBuddyDB = {
  _meta = { schema = 1, addon = "0.2.0", build = "1.60.1.70009", written = 1759616000,
            counts = { sessions = 3, events = 412, items = 88, bag_items = 61 },
            loaded_prior = true, truncated = false, secret_hits = 4, missing_events = {} },
  character = { ... }, snapshot = { ... }, items = { ... }, sessions = { ... },
}
```

`_meta.errors` (event → message, at most 200 characters) is present only if a handler failed, and the rest of the file is still written. A `/reload` writes the file and loads it again: the session carries on, joined on `PLAYER_ENTERING_WORLD`'s `isReloadingUi`, so it stays one session with the first login's `id` (if that event is missing or the reload didn't read the file back, a second session starts).

**Integrity: counts, not a checksum.** `_meta.counts` is written last in the logout handler from the tables it describes, each the number of entries in its table: `sessions`, `events` (summed over sessions), `items`, and `bag_items` (summed over `snapshot.bags[*].items`). Ingest recounts and rejects the file on any mismatch. A byte checksum would need Lua and Rust to serialize floats identically, which is fragile for no gain: the parser already rejects any truncation, so counts only need to catch a half-applied write.

## 3. Installing the addon

The app ships the addon from `src-tauri/resources/addon/ForeverBuddy/`, compiled into the binary (`include_bytes!` in `addon.rs`), so there's no resource path to resolve at runtime. The bundled version is the one the app expects (`schema = 1`); its TOC `## Version` is the bundled version.

| Command | Does |
|---|---|
| `addon_status() -> AddonStatus` | `{installed_version?, bundled_version, enabled_on: [char], disabled_on: [char], update_available}`. Reads `Interface/AddOns/ForeverBuddy/ForeverBuddy.toc` and each character's `AddOns.txt`. |
| `addon_install()` | Install or update. |
| `addon_remove()` | Deletes the bundled files by name (TOC first), then the folder only if it's empty: other files in it, and the folder, stay. Never recursive; a folder that's a link elsewhere is refused by the path check, not followed. Leaves the SavedVariables (they're the user's data). |

Install and remove go through the **write gate** (`MutationGuard`): refused while WoW runs (the UI shows the mock's "Close WoW first. Installing writes to your game folder."), with the gate's pre-write snapshot and `write_audit`. Each file is written with `atomic_write`, the `.toc` last, so a half-finished install has no TOC and WoW ignores it. Paths are `RelPath`s under `Interface/AddOns/ForeverBuddy/` only. The app doesn't edit `AddOns.txt`: a new addon is enabled by default, and "disabled on Kaelor" is reported, not overridden.

**Updates:** on app start, if the installed version is older than the bundled one, the Dashboard's step 1 shows "Update addon" (same gate). The app reads files from any `schema` it knows and ignores files with a newer one ("This addon file is from a newer Forever Buddy").

## 4. Ingest

### When to read

- **WTF watcher** (deferred here from T8): `notify` + `notify-debouncer-full` on `<flavor>/WTF/Account`, recursive. Only paths matching `<Account>/<group>/<character>/SavedVariables/ForeverBuddy.lua` are queued. The group is Forever's opaque id (`70`) or, in the older layout, the realm, and the character folder is the full name (`Ellygie-Vargur`) (matrix fact 5).
- **Settle:** a queued file is read once its size and mtime have been unchanged for 2 s (core-fs §3), then through `safe_read`.
- **Fallback scans**, because watchers miss events on network drives and while the app is closed: at app start, on every `Stopped` transition (after the exit settle the session worker already waits for), and every 10 minutes while WoW runs (`/reload`). A scan compares each file's `(size, mtime)` with `ingest_state` and queues changed ones.
- **Gap-fill from backups, at every start.** The file keeps only the last 10 sessions, so someone who plays 11 or more sessions without opening the app would lose the oldest. But every game-exit backup holds that logout's `ForeverBuddy.lua`. At start, before the live scan, ingest replays every snapshot newer than `meta.last_replayed_snapshot`, oldest first, reading each character's file from the backup store through the same validate-and-apply path (idempotent, so overlaps with live files cost nothing). This needs the app to run while WoW exits for the backup to exist; history from a session with the app closed throughout is recoverable only while it's still among the file's last 10.
- One **ingest worker** thread handles the queue in order, like the T14 session worker.

### Validate, then apply

1. `sv::parse` → exactly one global `ForeverBuddyDB`, a table. Otherwise: `skipped (parse)`, retry on the next change.
2. `_meta.schema` known, `_meta.counts` match. Otherwise `skipped (integrity)`.
3. The character must match its folder (case-insensitive).
   - **The rule:** the folder equals `character.name`, or `character.name .. "-" .. character.surname` when the addon recorded a surname. `UnitName`'s second return is the surname on Forever (probe run 1: `"Ellygie", "Vargur"`, folder `Ellygie-Vargur`).
   - **The realm isn't compared:** `GetRealmName` says "Classic Beta PvP 2" while the group folder is `70`.
   - **A missing name** (secret or unreadable) isn't a mismatch: the folder is used.
   - **Otherwise:** `skipped (mismatch)`. The folder wins, so a copied file can't impersonate another character.
4. Apply in **one transaction**, idempotent:
   - upsert `characters` by `(account, realm, name)`;
   - insert `char_snapshots` keyed by `(character, snapshot.at)` (same `at` = already ingested);
   - replace `char_items` for the locations present (`equipped`, `bags`; `bank`/`mail` only if their `at` is newer than what's stored);
   - upsert `items`;
   - for each `session`: upsert `adventures` by `(character, login)`, replace its `adventure_events`;
   - add `gold_points` from the snapshot and each session's `money` events.
5. Record `ingest_state(path, size, mtime, at, status, error)` and emit `ingest-completed {character}`. Failures show on the Dashboard's Game folder panel as "Couldn't read Thrandor's notes · will retry", never as a modal.

**Other players' data (PM decision).** Mail senders and subjects come from the user's own mailbox, so they're stored, locally only; the Mail tab is useless without them. They must **never** appear in CSV exports, logs, `ingest_state.error`, error messages or crash reports. Errors name the file and field, never a value. This is a test in V6 (a failing mail row's error text contains no sender) and in V8 (the CSV has no mail columns).

### Database (migration 004)

| Table | Key columns |
|---|---|
| `characters` | `id, account, realm, name, guid, class, race, sex, faction, level, guild, guild_rank, first_seen, last_seen` · unique `(account, realm, name)` |
| `char_snapshots` | `character_id, at, money, xp, xp_max, rested, level, ilvl_avg, ilvl_equipped, played_total, played_level, zone, subzone` · unique `(character_id, at)` |
| `char_items` | `character_id, location (equipped, bag, bank, mail), container, slot, item_id, link, count, as_of` |
| `items` | `item_id PK, name, quality, ilvl, icon_file_id, class_id, subclass_id, sell_price, seen_at` |
| `professions`, `lockouts` | per character, replaced per snapshot, with `as_of` |
| `gold_points` | `character_id, at, money` · unique `(character_id, at)` |
| `adventures` | `id, character_id, login, logout, play_session_id?, start_money, end_money, start_xp, end_xp, start_level, end_level, note` · unique `(character_id, login)` |
| `adventure_events` | `adventure_id, seq, at, kind, data (JSON)` |
| `ingest_state` | `path PK, size, mtime_ns, ingested_at, status, error` |

`adventures.play_session_id` links to T14's `play_sessions` by time overlap. When a process session has linked adventures, Recent sessions shows their characters instead of the mtime guess.

**The database stops being disposable.** core-fs treats `buddy.db` as a rebuildable cache, but gold history and adventures can't be rebuilt from the game's files (the file only holds the last 10 sessions). Two changes:
- **Daily copy:** `VACUUM INTO` `local_data_dir/db-copies/buddy-<date>.db`, keeping the last 7. A quarantined db restores the newest copy that opens cleanly.
- **Re-ingest from backups:** every full snapshot already contains each character's `ForeverBuddy.lua`. After a restore from copy, the app replays the snapshots newer than the copy through the same idempotent ingest, so nothing between the copy and the corruption is lost.

### Commands and events

`characters_overview() -> Vec<CharacterSummary>`, `character_detail(id) -> CharacterDetail` (gear, bags, bank and mail with `as_of`, professions, 30-day gold), `ledger(range) -> Ledger` (series per character + account, tiles), `adventures_list(range, character?)`, `adventure(id) -> Adventure` (tally, money series, timeline, gained, spent, quests), `adventure_set_note(id, text)`, `addon_status/install/remove`. Event `ingest-completed`.

## 7. Test plan (no WoW install needed)

1. **Addon logic in plain Lua 5.1 (CI):** a small harness (`tools/addon-test/`) loads `ForeverBuddy.lua` against a fake WoW API: tables for `C_Container`, `C_Item`, `UnitXP`…, an event bus, `issecretvalue`, and a clock. Scenarios: login → loot → sell → die → level → logout; secret values on every guarded call; an unknown event that throws; read-back missing; caps reached. Each scenario writes its `ForeverBuddyDB` with a WoW-style serializer to `src-tauri/tests/fixtures/addon/*.lua`.
2. **Those fixtures feed the Rust ingest tests:** apply → expected rows; apply twice → no change (idempotent); truncated file, wrong counts, unknown schema, name/folder mismatch → skipped with the right status and nothing written; bank `at` older than stored → bank kept; two characters in one game session → two adventures linked to one `play_session`.
3. **Watcher:** temp dir, write the file in chunks → one ingest after it settles; a file changed during `safe_read` → retried.
4. **DB safety:** corrupt `buddy.db` → newest copy restored → snapshot replay restores the missing adventures.
5. **Install:** gate refusals with `FakeProbe(running)`, TOC-last ordering (kill after the first file → no TOC), remove keeps SavedVariables.
6. **UI:** the mock-IPC harness from T11/T14 under the app's CSP, one scenario per state (no addon, addon outdated, fresh data, secret-heavy session, stale bank).
7. **Live (Julia, once per milestone):** the probe first (gate G1), then a scripted 20-minute session after V4 lands, compared against the Adventure screen.
