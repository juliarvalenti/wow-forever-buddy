## 5. Building the UI

This chapter covers how EllesmereUI draws and runs its windows: pixel-exact sizing, colours and fonts, settings pages built from small widget builders, and the window's popups, tooltips, minimap button and saved position. The one idea to remember: build every frame once, bind it to get and set functions over saved data, and refresh it in place, because WoW never frees a frame.

### Pixels and scale

**5.1 Compute one physical pixel from WoW's 768-unit height and snap sizes and offsets to it.**
EllesmereUI derives "1 physical pixel" as `768 / physicalHeight / UIParentScale` and rounds sizes and offsets to whole multiples of it, with a 0.001 epsilon because "float dust can land a hair below, dropping a whole pixel at floor". Note that after load its multiplier divides by the saved UI scale, not the live `UIParent:GetScale()`. `PP.Scale` truncates toward zero, and `PP.Snap` is the round-to-nearest variant.
Source: `EllesmereUI_PixelPerfect.lua:22-26,65-69,118-139`.
```lua
local function Snap(x)
  local m = 768 / physH / UIParent:GetScale()
  return math.floor(x / m + 0.5) * m
end
```
For ForeverBuddy: only needed where we draw our own hairlines; the `ButtonFrameTemplate` chrome of our 360x420 window already handles itself.

**5.2 Draw thin borders from four solid textures with pixel snapping turned off.**
EllesmereUI builds borders as four WHITE8X8 strips on a child frame one level above the host, because "NineSlice corner sub-frames render as black boxes on nameplates". Every strip, divider, toggle track and grid line calls `SetSnapToPixelGrid(false)` and `SetTexelSnappingBias(0)`: "a 1px edge strip must never round to 0 and VANISH per-side at fractional scales/positions". It re-snaps for two frames after creation to catch the final scale.
Source: `EllesmereUI_PixelPerfect.lua:304-326,754-765,785`; `EllesmereUI.lua:1208`.
For ForeverBuddy: any divider or row highlight we add inside the window's tabs should turn snapping off on its texture.

**5.3 Give a custom window its own scale, seeded from screen height, clamped and stepped.**
EllesmereUI's panel sets its scale to `GetScreenWidth()/physW * userScale` in every OnShow, so one unit is one screen pixel whatever the UI Scale setting. First installs seed the user scale at `physH/1440` clamped to 1-2, since on 4K "the panel arrives unreadably small". The user range is 0.75 to 2.00 in 5% steps, set by slider or Shift plus mouse wheel. Their OnShow divides by `GetPhysicalScreenSize()` with no zero guard, which 5.5 says to avoid.
Source: `EllesmereUI_Panel.lua:206-212,239,660-663`; `EllesmereUI_Startup.lua:144-146,164`; `EllesmereUI_Lite.lua:27-37`.
For ForeverBuddy: our window follows UI Scale today, which is fine; if users ask for a size option, store one clamped `windowScale` in `ForeverBuddySettings`.

**5.4 Re-apply your scale on `UI_SCALE_CHANGED`, `DISPLAY_SIZE_CHANGED` and `PLAYER_ENTERING_WORLD`, and never set UIParent's scale yourself.**
EllesmereUI's scale watcher listens to those three events. It notes that "UIParent:SetScale() does NOT fire UI_SCALE_CHANGED (that event is CVar-tied)", so its own scale path re-snaps by hand and defers through a combat queue. It changes UIParent's scale on a display change only if the user opted in.
Source: `EllesmereUI_PixelPerfect.lua:73-77,100-103,937-947`.
For ForeverBuddy: only relevant if we adopt 5.3; then the same three events refresh the window's scale.

**5.5 Before dividing by a width, height or scale, check it is a positive finite number.**
EllesmereUI keeps the last good screen height when `GetPhysicalScreenSize()` reports 0 mid display change, falling back to 1920x1080, because "768/0 is infinite" and spreads NaN sizes. Separately, its author writes that "WoW Forever's Lua raises an error on a division by zero or with a NaN or infinite operand (retail yields NaN or inf quietly)". That second statement is the author's comment with no test beside it, and the code hedges by probing NaN behaviour under pcall. Guard either way: an error and a NaN both break the frame.
Source: `EllesmereUI_PixelPerfect.lua:41-50,155-174`; commit `5003f6a6`.
For ForeverBuddy: any layout maths in `ForeverBuddy.lua` that divides by `GetWidth()`, `GetHeight()` or a scale (the minimap drag does) should check the divisor first.

### Look, colour and fonts

**5.6 Keep every colour and alpha in one style table, and draw borders and secondary text as white with alpha.**
EllesmereUI holds its widget colours in one `STYLE` table, "one table instead of ~75 file-scope locals, which would push this main chunk past Lua 5.1's 200-active-locals limit". Borders, text and slider tracks are white with alpha, which "adapts to any background tint".
Source: `EllesmereUI.lua:162-189`.
For ForeverBuddy: `ForeverBuddy.lua` is already at the 200-locals limit, so new colours go into a table (an existing one like `S`, or a new `STYLE`), never new top-level locals.

**5.7 Build chrome from solid colour textures, and preload any large background art off-screen.**
EllesmereUI's panels, rows, buttons and borders are `SetColorTexture` fills. The only big art is the panel background, loaded by a hidden 1x1 frame far off-screen: "no 1-frame bg flash on first open".
Source: `EllesmereUI.lua:124-130,1111-1115`.
For ForeverBuddy: if a P4 module ships its own background image, preload it the same way at login.

**5.8 Get drop shadows from a FontObject, and build outline flags in one helper.**
The author writes that "Runtime FontString:SetShadowOffset/SetShadowColor does NOT render a drop shadow; shadows only render when carried by a FontObject", so each string gets a shared shadow FontObject first and then `SetFont`. This is their comment, not something we have tested. Outline flags all come from `GetFontOutlineFlag`, and `SlugFlag()` strips `, SLUG` when the user turns the Slug outline off. Which clients render the Slug outline is not stated in their source.
Source: `EllesmereUI_Fonts.lua:357,393-404,413-418,434-451`.
For ForeverBuddy: we use stock font objects (`GameFontHighlight` and friends), which carry their own shadow; this only matters if we call `SetFont` with a bundled face.

**5.9 If you use LibSharedMedia, fetch it silently and refresh your font cache when fonts register late.**
EllesmereUI gets LSM with `LibStub("LibSharedMedia-3.0", true)`, registers its fonts, and listens for `LibSharedMedia_Registered`. That late callback must also invalidate its font cache, or "the Expressway fallback" stays cached "for the session". In CallbackHandler, the same owner on the same event replaces the earlier callback, so their texture callback uses its own owner table.
Source: `EllesmereUI_Fonts.lua:101-121,136-138`; `EllesmereUI.lua:3002`.
For ForeverBuddy: we do not use LSM; keep it that way unless users ask for font choice.

**5.10 If you bundle a font, swap to the client's own font where yours lacks the glyphs.**
EllesmereUI uses its house font only where it covers the script. zhCN, zhTW and koKR get the client's fonts, and ruRU keeps only faces that cover Cyrillic, since a wrong entry "would render boxes".
Source: `EllesmereUI.lua:1104-1106`; `EllesmereUI_Locale.lua:125-128`; `EllesmereUI_Fonts.lua:43-49`.

### Settings pages and widgets

**5.11 Write each control as a builder that returns its frame and height, and stack a page by subtracting heights.**
EllesmereUI's widget calls take `(parent, text, yOffset, getValue, setValue, tooltip)` and return the row and its height. A page is a list of calls that do `y = y - h`, and returns the total so the scroll child can be sized. No layout engine is needed (our inference).
Source: `PLUGINS_API.md:30-38`.
```lua
local y = -8
local _, h = W.Header(page, "Merchant", y); y = y - h
_, h = W.Toggle(page, "Sell grey items", y, getSellGreys, setSellGreys); y = y - h
page:SetHeight(-y)
```
For ForeverBuddy: the Settings tab's `buildOptions(p, -8)` and the settings page P4 adds should follow this shape, so each module adds rows without touching the others.

**5.12 Bind every control to get and set functions over saved variables, and give it a `Refresh()` that re-reads `get`.**
An EllesmereUI toggle keeps the two closures, wraps the setter to mark settings as changed, and registers a refresh callback "so RefreshPage updates values in-place without rebuilding frames". A reset or profile switch then calls the refreshes and builds nothing.
Source: `EllesmereUIOptions/EllesmereUI_Widgets.lua:111,2308-2331`; `EllesmereUI.lua:1083`.
For ForeverBuddy: when the companion app or Claude changes `ForeverBuddySettings`, the open Settings tab should refresh its controls from `get`, not keep showing the old values.

**5.13 Build each page once, keep it, and reuse row frames from a pool.**
EllesmereUI caches built pages for the session: "frames can never be freed, so dropping them on close would only turn every revisit into a rebuild." Its frame pool exists because "WoW never frees a frame, so a settings page that is built again must not build new frames." Search stopped pre-building hidden pages after finding they made "10-25MB of permanent frames".
Source: `EllesmereUI_Panel.lua:235-236`; `EllesmereUIOptions/EllesmereUI_FramePool.lua:5-7`; `EllesmereUI_GlobalSearch.lua:514-516`.
For ForeverBuddy: the Plan, Lists, Errands and Cleanup tabs should refill a fixed set of row frames on refresh, and create more only when a list grows past them.

**5.14 Build the window on first open, and split a heavy first build across two frames.**
EllesmereUI's settings live in a separate LoadOnDemand addon. The first open only loads it, and the panel is built on the next frame with `C_Timer.After(0, ...)`, because doing both in one click hit "'script ran too long' aborting mid-sidebar on the very first open". A pending flag ignores repeat clicks meanwhile.
Source: `EllesmereUIOptions/EllesmereUIOptions.toc:8-9`; `EllesmereUI_Panel.lua:5371-5394`.
For ForeverBuddy: our window already builds in `build()` on first open; if a P4 settings page makes that slow, defer its build by one frame rather than splitting into a second addon.

**5.15 When a control is disabled, say why in its tooltip.**
EllesmereUI rows can carry `disabled` and `disabledTooltip`. A mouse overlay is active only while the control is disabled and shows "This option requires %1$s to be %2$s", with positional slots so translators can reorder words.
Source: `EllesmereUI_UICore.lua:208-209`; `EllesmereUIOptions/EllesmereUI_Widgets.lua:403-408`.
For ForeverBuddy: options in the Settings tab that depend on another (for example a module's sub-options) should name the parent setting on hover.

### The window

**5.16 Let Escape close the window through `UISpecialFrames`, and use one proxy only when you have several windows.**
EllesmereUI adds one hidden proxy frame to `UISpecialFrames`. Its windows register with it, and each Escape press closes the newest open one. Modal frames swallow Escape so the user must click a button.
Source: `EllesmereUI.lua:3958-3964,3982-3984,4100-4113`.
For ForeverBuddy: `tinsert(UISpecialFrames, "ForeverBuddyWindow")` is right for one window; revisit if P4 modules open windows of their own.

**5.17 If the window touches anything combat protects, close it when combat starts and refuse to open it in combat.**
EllesmereUI hides its panel on `PLAYER_REGEN_DISABLED` with a chat line, and `Show` refuses under `InCombatLockdown()`, because "Pages built then would call widget methods that are blocked in combat." Closing still works through Toggle. One slip: their minimap click returns early on every button in combat, so it cannot close the panel either.
Source: `EllesmereUI.lua:3851,3934-3940`; `EllesmereUI_Panel.lua:5399-5405,5416-5421`.
For ForeverBuddy: our window is read-only in combat (the tracker checkbox checks `InCombatLockdown`), so it may stay open; keep closing possible from every path.

**5.18 Keep a fixed strata ladder, and close custom menus on an outside click.**
EllesmereUI puts its panel on DIALOG at level 100, dropdown and pick menus on FULLSCREEN_DIALOG at 200 to 220, confirm popups on FULLSCREEN_DIALOG at about 100 to 110, and its widget tooltip on TOOLTIP. A pick menu closes through a full-screen invisible button at level 210, just under the menu, that hides it on any click; other dropdowns poll for a left click outside menu and button.
Source: `EllesmereUI_Panel.lua:201-202`; `EllesmereUIOptions/EllesmereUI_Widgets.lua:508-510,1396,2736,2744-2749`; `EllesmereUI_Popups.lua:103,557`; `EllesmereUI_UICore.lua:226-227`.
For ForeverBuddy: our window sits on HIGH; any dropdown or confirm we add goes on FULLSCREEN_DIALOG, clamped to the screen.

**5.19 Save the window's position in your own saved variables, as a CENTER offset from UIParent's center.**
EllesmereUI stores "All elements ... as CENTER/CENTER (offset from UIParent center)", converted from the frame's edges with the scale ratio applied, so positions survive resolution changes. Most modules keep the position in their own profile through a `savePos` callback with a default when missing, though unlock mode writes action-bar positions itself. For one window, plain `StartMoving` and `StopMovingOrSizing` is enough; their grid and edge snapping only pay off with many movers.
Source: `EUI_UnlockMode_Positions.lua:2210-2240,2427-2448`; `EllesmereUIResourceBars/EUI_ResourceBars_ArcaneSoul.lua:1031-1044`.
For ForeverBuddy: the title-bar drag already saves `cfg().window = { point, rel, x, y }` from `GetPoint()`; normalising it to a CENTER offset would keep it on screen after a resolution change.

### Popups, reloads, tooltips, minimap

**5.20 Build one reusable confirm popup on a full-screen dimmer instead of using StaticPopup.**
EllesmereUI never calls `StaticPopup_Show`. Its contributing guide says "`EllesmereUI:ShowConfirmPopup`, never `StaticPopup_Show`", since it is the one that "inherits the panel skin and the scale registry". The dimmer covers the screen and eats clicks and the mouse wheel.
Source: `EllesmereUI_Popups.lua:87-95`; `.github/CONTRIBUTING.md:68`; `EllesmereUIQoL/EllesmereUIQoL_RaidTools.lua:879-881`.
For ForeverBuddy: one confirm frame, built on first use and refilled with title, text and two buttons, covers any P4 reset or uninstall step.

**5.21 Make key-listening frames pass every key except the ones they handle, and never change keyboard settings in combat.**
An EllesmereUI popup calls `EnableKeyboard(true)` and `SetPropagateKeyboardInput(true)` only out of combat, because both "are protected in combat". Its OnKeyDown swallows Escape alone and does nothing in combat. Without propagation, a shown popup would eat movement keys.
Source: `EllesmereUI_Popups.lua:128-140`.

**5.22 On Forever, call `ReloadUI()` only from a click or keypress, and ask for it before the click does anything else.**
EllesmereUI's key sentence: "WoW Forever lets addon code reload only inside a click or keypress (in or out of combat), never from an event or a timer". It adds that build 70425 "refused a reload asked for late in the click, after the confirm popup had closed and the caller's work had run", so `RequestReload` calls `ReloadUI()` first and runs the caller's work after: "The client reloads only once the click's code has finished, so `work` still runs and is saved." Code that may run from an event shows a confirm popup whose button does the reload. In practice "first" means before the real work and before the popup closes: some callers run cheap checks or stamp a flag first, and `/rl` calls `ReloadUI()` directly from its slash handler. This rests on one comment; nothing in their repo tests it. Their own `PLUGINS_API.md` contradicts it, telling plugin authors to call `RequestCDMRepopulate()` and then a bare `ReloadUI()`.
Source: `EllesmereUI_Popups.lua:524-538,770-787`; `EllesmereUI_Startup.lua:522-528`; `PLUGINS_API.md:216-226`.
```lua
syncButton:SetScript("OnClick", function()
  ReloadUI()      -- ask first, inside the click
  saveState()     -- then the rest; it still runs before the reload
end)
```
For ForeverBuddy: our window says "Type /reload to sync" because bridge-v0.4 §4 assumed ReloadUI is protected on Forever (see the comment above the window block in `ForeverBuddy.lua`). If this holds, a plain button whose OnClick calls `ReloadUI()` first could replace typing. Confirm it in game before relying on it.

**5.23 Reuse one tooltip for every hover, and skip hover work in instanced combat.**
EllesmereUI's widget tooltips use one lazily created TOOLTIP-strata frame. They are suppressed in active M+, and in raid and PvP combat, because "frame APIs return secret values in tainted execution". The tooltip text goes through the locale function.
Source: `EllesmereUI_UICore.lua:223-227,264-270,294`.
For ForeverBuddy: our minimap and window tooltips already use `GameTooltip` with `SetOwner`; keep it that way.

**5.24 Build a native minimap button: a saved angle, a drag OnUpdate, a tooltip for each click, and a saved hidden flag.**
EllesmereUI's "Native Minimap Button (no library dependencies)" is a 32px Button on `Minimap` placed at a saved angle, dragged by an OnUpdate that turns the cursor into an angle, with stock border and highlight art. Middle-click hides it and saves the choice. It ships LibDataBroker only to read other addons' broker objects and never registers its own.
Source: `EllesmereUI.lua:3776,3795-3819,3843-3862`; `EllesmereUI.toc:17`; `EllesmereUIDataBars/EllesmereUIDataBars.lua:3178-3186`.
For ForeverBuddy: our button already matches this (`minimapAngle`, right-click hides, `/fb minimap` brings it back); add LibDBIcon only if users ask.

### First run and localisation

**5.25 Gate a welcome panel on a saved flag, skip it for users who already have data, and show it shortly after login.**
EllesmereUI decides at ADDON_LOADED: if any profile already holds data, the user is treated as upgrading, the "shown" flag is stamped and nothing appears. Otherwise the popup shows 0.5 s after PLAYER_LOGIN. Its style picker closes on Escape with "nothing written".
Source: `EllesmereUI_FirstInstall.lua:545-562,577-596`; `EllesmereUI_StyleChoicePopup.lua:4-14`.
For ForeverBuddy: if P4 adds an intro to modules, existing `ForeverBuddyDB` data marks the user as upgrading, and the login briefing stays the first thing they see.

**5.26 Translate at the `SetText` call, use the English text as the key, and fall back to it silently.**
EllesmereUI's rule is "translate the pixels, never the data": `L(s)` returns the input on English clients or when a key is missing, and only the widget builders call it, so internal identifiers stay English. `Lf` uses positional `%1$s` slots, and translations live in a LoadOnDemand addon English clients never load.
Source: `EllesmereUI_Locale.lua:9-11,60-78`; `AGENTS.md:23-24`.
For ForeverBuddy: wrap visible strings as `L("...")` where text is set, never on keys in `ForeverBuddyDB` or `Data/*.lua`.

### Not for us
- Accent colour registries shared across modules (finding 8); one style table (5.6) is enough until users can pick a theme.
- Global search over settings rows and the "absorber" stub that indexes unopened pages.
- A LoadOnDemand options addon; one file with a lazily built page (5.14) is enough at our size.
- Unlock mode: the movers grid, edge snapping, snapshots with Save and Discard, and Edit Mode coexistence. Chapter 3 covers not moving Blizzard frames and keeping state off them, which P4 bars and frames will need.
- The optional EllesmereUI Skin API hook; our window should stand on its own look.
